# OctoAcme Project Management Processes

This folder contains OctoAcme's program-level project management process documents. The docs describe how we initiate and validate work, plan and prioritize the backlog, execute and track delivery, run releases and deployments, capture retrospective improvements, and manage risks and stakeholder communication. These artifacts and templates provide a single source of truth for onboarding, consistent execution, and continuous improvement across projects.

## Overview (short)
OctoAcme follows an iterative, evidence-driven approach. Projects start with a lightweight initiation (one‑pager) to confirm goals and stakeholders, move into planning to produce a prioritized backlog and release milestones, then execute in short increments with clear acceptance criteria and CI-based quality checks. Releases follow a checklisted deployment process with smoke tests and rollback plans. Retrospectives turn learnings into tracked action items, while a maintained risk register and a defined communication cadence keep stakeholders aligned. Roles (PM, PdM, Developers, QA) and key artifacts are documented to ensure consistent delivery.

- docs/octoacme-roles-and-personas.md — Role definitions and responsibilities used across the process docs.

## How to contribute
If you'd like to update or add a process doc, please open an issue using the provided template (.github/ISSUE_TEMPLATE/add-update-content-to-process-docs.yml) describing the change, suggested content, and rationale. Use the project board to link and track work, and include reviewers for process changes.
